Two defects found and fixed on the way:

1. **Registry paths written by Git Bash.** `install.sh` records the project as `/c/Users/...`;
   native Windows Python cannot open that, so the doctor warned "workspace is not registered"
   and recall skipped the project. `native_path()` in `agent-spec-doctor.py` and
   `agent-spec-recall.py` maps `/x/...` to `X:/...` on Windows only. Test:
   `test_registry_paths_from_git_bash_map_to_windows_drives`.
2. **Digest check hung on an open stdin.** The doctor ran `digest --cursor-hook` with the
   doctor's own stdin. Hook mode reads stdin to EOF; under any non-tty stdin that stays open
   (`curl … | bash`, a CI step, a pipe from another shell) EOF never comes, so the check hit
   its 15 s timeout and `--register` reported `FAIL digest — digest --cursor-hook did not emit
   JSON` while a standalone doctor run was green. The doctor now runs every child with
   `stdin=DEVNULL`. Test: `test_digest_check_does_not_wait_on_an_open_stdin`, which fails
   after 17 s without the fix.

`expanduser` on Windows Python reads `USERPROFILE`, not `HOME`: a test that only overrides
`HOME` writes into the real profile. The run above set both.
