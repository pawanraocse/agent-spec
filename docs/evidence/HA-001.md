# HA-001…HA-006 — Harness automation

Built 2026-11-14.

## Why

An audit of every `bin/` script, hook and skill asked one question of each: does it run
because a hook calls it, or because a person or the model remembers to? Most of the
upkeep was already automated (digest, doctor line and graph refresh at session start;
git-hook re-indexing on checkout, merge and rewrite; receipts; the context nudge). Three
deterministic steps were not:

| Step | Who had to remember | Source of the instruction |
|---|---|---|
| Run `/agent-spec-snapshot` on a long chat | the model, after reading a sentence | `hooks/cursor-session-end.py` follow-up text |
| Re-index after a mid-session add, move or rename | the model | `skills/agent-spec-index-project/SKILL.md` ("Re-run after any change that moves or renames files") |
| Rotate `SESSION-SNAPSHOT.md` | the snapshot skill's last step | `skills/agent-spec-snapshot/SKILL.md` ("Run it after appending") |

All three are plumbing (DEC-15): no judgement moved into code.

## What changed

| Row | Hook | Behaviour |
|---|---|---|
| HA-001 | `stop` / `sessionEnd` (`cursor-session-end.py`) | The long-chat follow-up is exactly `/agent-spec-snapshot`, the same mechanism the hook-probe collect turn uses. Still one per chat (`.snapshot-nudged-<session>`). |
| HA-002 | `afterFileEdit`, `postToolUse` (`cursor-event.py`) → `stop` / `sessionEnd` | The event spine writes `.agent-spec/.graph-dirty` after an agent edit or a `Shell`, `run_terminal_cmd`, `Write`, `Delete` or `delete_file` tool call. The session-end hook spends the marker and starts `graphify-build.py --quiet` detached. The builder's incremental cache keeps a run short, and its lock makes an overlapping run a no-op. No marker, no build. |
| HA-003 | `sessionEnd` | `agent-spec-memory.py rotate`, 3 s timeout, output discarded, fail-open. Under the threshold it is a no-op. `stop` does not run it. |

Both upkeep steps run before the receipt debounce and before any follow-up returns, so neither
is skipped by an early return.

## HA-004 — dropped

The proposal was to have `stop` return `/agent-spec-sdlc` when the current gate's artifact
exists. `skills/agent-spec-sdlc/SKILL.md` says "One gate per invocation. Do not chain. Every
gate is a separate human approval", and a `followup_message` is submitted without one. The
session-start digest already reports the pipeline state, so nothing was built.

## Tests

`tests/test_session_end.py`: the follow-up equals `/agent-spec-snapshot`; a clean graph
starts no build; a dirty graph starts `graphify-build.py --quiet` and spends the marker;
`sessionEnd` rotates and `stop` does not; a failing rotate or build still prints `{}`.
`tests/test_cursor_event.py`: a Read leaves the graph clean; `afterFileEdit` and a `Shell`
`postToolUse` mark it dirty.

## HA-005 — one-command project readiness

`bin/agent-spec-ensure.py` replaces three sentences of preflight prose (`agent-spec-raw-code-full`
§0, the router, `CURSOR.md`) with one command. The prose covered only a missing `.agent-spec/`.
The script also catches merged hooks that went missing and a rules file older than the
package VERSION, and it builds a missing graph. Onboarding stays a skill: the script reports
`"next": "/agent-spec-onboard"` from the installer's `.onboarding-needed` flag, and the model runs
it.

Measured on a throwaway git project with a fake `HOME`: first run `registered: installed` in
0.72 s wall time (install 603 ms), second run a no-op, a rules file stamped `1.9.0` re-registered
in 540 ms, and `$HOME` refused with exit 1. `tests/test_ensure.py` has eight cases.

## HA-006 — Automations panel

| Piece | Where |
|---|---|
| Run log, one row per run | `.agent-spec/metrics/automation.jsonl` (`ts`, `name`, `status`, `reason`, `duration_ms`, `session`, `source`) |
| Switches | `.agent-spec/automation.json` `{"disabled": [...]}`, read by `cursor-session-end.py` and `agent-spec-ensure.py` |
| API | `GET /api/automations`, `POST /api/automations {id, enabled}` in `bin/aspec_platform/serve.py`, module `bin/aspec_platform/automations.py` |
| UI | Project › Automations, `ui-src/src/pages/Automations.tsx` |

Every count is measured from the log; there is no time-saved figure, because nothing measures
the time a person would have spent. An environment opt-out (`AGENT_SPEC_AUTO_REGISTER=0`,
`AGENT_SPEC_CONTEXT_NUDGE=0`) wins over the switch, and the panel shows the switch locked.

Live check on 2026-11-14 against `agent-spec-platform.py serve` on the throwaway project: one real
`sessionEnd` left `graph-refresh started` and `snapshot-rotate ok (41 ms)`. `GET` returned both, and
`POST {"id": "snapshot-followup", "enabled": false}` wrote `{"disabled": ["snapshot-followup"]}`.
`tests/test_automations.py` (5) covers the counts, the round trip and the guards (401, 403, 415,
unknown id, non-boolean). The UI honesty test covers the page.

Not verified: the panel was not opened in a browser (Playwright is not installed here). The
SPA route returned 200 and the vitest render passed.
