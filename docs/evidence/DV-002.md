# DV-002 evidence (2026-11-13, partial)

## Root cause of "no live payloads"

Cursor's hook log (`cursor.hooks.*.log` under the Windows Cursor `logs/` directory) shows that
no agent-spec hook has ever run in the Cursor IDE on this machine. Every invocation logs:

```
execution error: spawn powershell ENOENT
```

Windows Cursor opens this repo as `file://wsl.localhost/Ubuntu-22.04/...` instead of through
Remote-WSL. It therefore spawns `python3 .cursor/hooks/...` on Windows, where the spawn fails.
It also passes `workspace_roots` as `/Ubuntu-22.04/home/...`. The only `exit code: 0` entries
in those logs belong to another plugin's hooks. The fix is to open the folder inside WSL:
`cursor --remote wsl+Ubuntu-22.04 <path>`. The Remote-WSL extension
`anysphere.remote-wsl-1.0.13` is already installed.

## Recording without an environment variable

Cursor logs the full INPUT of every hook invocation even when the hook cannot start, so the
log itself is the recording. `bin/aspec_platform/hook_logs.py` and
`agent-spec-platform.py hooks` read it:

| Flag | Effect |
|---|---|
| (none) | Invocation and failure counts, distinct reasons, and the fix when the cause is known |
| `--payloads` | Latest payload per event into `.agent-spec/metrics/hook-payloads/` |
| `--fixtures DIR` | The same payloads, with email, local paths and ids masked, for committing |
| `--backfill` | Missing rows appended to `events.jsonl` through the hook's own `handle_event` |

The dashboard server runs the backfill on startup and every 60 s
(`AGENT_SPEC_HOOK_LOG_BACKFILL=0` turns it off). Cursor sessions therefore appear as traces
with no manual step, even while the hooks themselves fail.

## Live probe, 2026-11-13 (Cursor 3.30.8, Remote-WSL)

`/agent-spec-hook-probe` ran in the Cursor IDE and collected its own results through the
`stop` hook's follow-up message. `agent-spec-platform.py hooks` afterwards:

```
hook invocations: 84 (16 failed) | events: afterAgentResponse, afterFileEdit, beforeSubmitPrompt, postToolUse, postToolUseFailure, preToolUse, sessionEnd, sessionStart, stop, subagentStart, subagentStop | cursor 3.30.8
coverage: 11/12 registered events fired
  missing preCompact           fires only when Cursor compacts a long chat
```

`tests/fixtures/hooks/recorded/` now holds a real payload for 11 events. Two findings came out
of the real payloads and were fixed with tests:

- A subagent's tool calls arrive under its own `child_conversation_id` and point back with
  `parent_tool_call_id`, which equals the parent's `subagent_id` (a tool-call id, not a
  conversation id). The trace builder keyed only on conversation id, so these calls became an
  orphan trace. `cursor-event.py` now keeps `parent_tool_call_id` and `child_conversation_id`;
  `traces.build_from_events` nests by them (`tests.test_traces`, `tests.test_cursor_event`).
- `sessionEnd` on `window_close` fails with `Error: MainThreadShellExec not initialized` in
  Cursor 3.30.8. `diagnose` used to clear any failure once another hook succeeded, which hid
  it; failures now stay current until the same event succeeds. The stop hook writes the same
  receipt, so no data is lost and the dashboard shows it amber, not red.

Exception accepted at close: no live `preCompact` payload. The trace builder parses it from the documented contract, `agent-spec-platform.py hooks` lists it as missing, and the 60 s backfill records the first real one without a code change.
