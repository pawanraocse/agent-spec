# H-053 — timed dry runs of the 5-minute demo

## 2026-11-18 — scripted dry run, network off

`examples/mesh-demo/demo-dryrun.py` builds the demo with `demo-setup.sh` in a throwaway
directory under a temporary HOME, then drives every beat of `demo.md` with the presenter's
commands and the dashboard calls the buttons make (real server, loopback). On Linux it runs
inside `unshare -rn`, where only loopback exists.

Two runs, both offline, 10 of 10 beats each:

| Beat | Run 1 | Run 2 |
|---|---|---|
| setup (off stage) | 2.06 s | 2.03 s |
| digest | 0.13 s, 820 B | 0.13 s, 820 B |
| cross-repo blast radius + recall | 0.04 s | 0.05 s |
| tier-3 blocked / approved | 0.01 s / 0.01 s | 0.01 s / 0.01 s |
| impact | facts: routes are a public contract | same |
| proposal approved | 0.06 s | 0.06 s |
| audit export + tamper check | 0.10 s, 7 lines | 0.10 s, 7 lines |
| total | 2.9 s | 2.8 s |

Failures found by the first runs and fixed before the counted two:

1. The Impact beat showed no injected facts. `hooks/cursor-session-start.py` recorded the
   injection only when `.agent-spec/metrics/` already existed, so a freshly registered
   project lost its first chat's record. It now creates the folder (also H-005).
2. The digest on stage opened with "ONBOARDING NEEDED". Onboarding is an agent action;
   `demo-setup.sh` now writes the two onboarding files for `orders-api` and clears the flag.
3. The demo memory was empty, so the digest and Impact had no fact to show. Setup now
   remembers one fact and proposes a different one for the proposal beat.

Tests: `tests/test_demo_setup.py` (8) covers the injection record, the digest and a full
dry run.

Owed: two rehearsals by the presenter on the demo machine, timed against the 5-minute
script. The script checks the product, not the talk.
