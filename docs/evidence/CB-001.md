# CB-001…CB-005 — Measured context budget and warm resume

Built 2026-11-13. Every number below was read from this machine, not assumed.

## Why this, and not something else

`agent-spec-tokens.py --claude corpus` over 413 local sessions (78 projects, 163,208 assistant
turns) put cache reads at **69.5%** of the weighted bill. Context at the last turn averaged
**4.7x** the first (45,276 → 212,423 tokens). Tool results were 0.61% of the bill. So the largest
lever is how long a chat carries its context, not tool output. The repository's own guidance
(`agent-spec-raw-code-full` §6) already called a reset "the largest single move", but nothing
told the developer *when* a reset pays.

## What Cursor measures (and what it does not)

| Source | Field | Meaning | Used as |
|---|---|---|---|
| Cursor local store, `composerData:<id>` | `contextTokensUsed`, `contextTokenLimit` | the context one model call sends now | **context size** |
| same | `promptTokenBreakdown.categories` | Cursor's split: system prompt, tools, rules, skills, MCP, subagent definitions, conversation (Cursor labels these estimated) | the chat's **fixed part** = everything but the conversation |
| `afterAgentResponse` hook | `input_tokens`, `cache_read_tokens` | tokens billed for the whole request (every call in the agent loop) | billed trend only |

`afterAgentResponse` is **not** a context size: a trivial "hi" request billed 36,176 input tokens
and a request with two subagents billed 157,633, after which the next request billed 92,114. A first
draft used these as context and was replaced before shipping.

Subagent composers are excluded from the fresh-chat floor (they start from a task, not the rules):
with them the floor read 15,704; without them 18,489.

## Arithmetic (CB-001, exact computation)

Same weights and threshold as `agent-spec-tokens.py context` (read 0.1, write 1.25, reset under 5):

```
carry      = used  x 0.1      reset_once = fixed x 1.25
after      = fixed x 0.1      break-even = reset_once / (carry - after)   model calls
```

`fixed` is the chat's own non-conversation categories; without a breakdown, the smallest measured
fresh-chat size on the machine (`context_budget.machine_floor`).

Live result on 2026-11-13, "Agent spec snapshot review": 118,311 tokens, of which 95,651 conversation
and 22,660 fixed (tools 8,514, rules 5,610, skills 3,799, MCP 3,111, subagent definitions 1,155,
system prompt 471). Break-even 3.0 calls, saving ~9,565 weighted tokens per call after. 1 of 10
chats was past break-even.

## CB-002 — stop hook (hook rung)

`hooks/cursor-session-end.py` → `context_nudge()` loads `context_budget.py` and `cursor_sessions.py`
by path (DEC-03: no package import from the harness) and returns one `followup_message` per chat when
the verdict is `reset`. Run against the live store from a scratch project:

```
{"followup_message": "Agent-Spec context check (Cursor's own counter): this chat re-sends 118,311 tokens on every model call, 5.22x a fresh chat (22,660). A new chat pays for itself in 3.0 calls and saves ~9,565 weighted tokens per call after that. Run `/agent-spec-compact` to write the state to disk, then tell me to continue in a new chat."}
```

Cost: one indexed read of the store; 0.26 s for the WAL snapshot copy on WSL (22 MB store + 5.5 MB WAL).
Off with `AGENT_SPEC_CONTEXT_NUDGE=0`.

## CB-005 — AF-004 snapshot nudge never fired (bug)

Two faults in the old code: the one-shot marker was written on the first `stop` before the size check,
and `receipt.get("tokens", 0) > 40000` compared the receipt's `tokens` **dict** to an int, which raises
`TypeError`; `__main__` swallowed it and printed `{}`. Both fixed; regression test
`test_snapshot_nudge_fires_on_a_long_chat_and_not_before`.

## CB-003 — UI

- Live › request › **Context** tab: verdict banner, composition bar scaled to the window with the
  fresh-chat line, per-category legend, the arithmetic on demand, per-request billed bars with the
  current request highlighted, copy `/agent-spec-compact`. Header chip on every request.

All figures render through `<Num>`; the honesty test covers the Coach panel and the Context tab.

## CB-004 — warm resume in the digest (hook rung)

The digest's `last_snapshot_summary` looked for `# Session Snapshot` / `## Session Summary`, a format
the snapshot skill no longer writes, so the digest had no `last session:` line. This session had to
read the snapshot (9,441 B tool result) to learn what was open. `resume_lines()` now takes the newest
`## YYYY-MM-DD …` section's title, `### Load next session` and up to three `### Open` items, capped at
600 B (489 B on this repository; digest 2,226 of 2,600 B).
