# H-043 — Scale check (2026-11-18)

Machine: WSL2 on the development laptop, Python 3.12.2.

## Graph build, synthetic 20,000-file Python repo (3 imports per file)

| Run | Before | After |
|-----|--------|-------|
| Full build (`--rebuild`) | 4.46 s, 126 MB RSS | 4.28 s |
| No-op incremental (sessionStart, nothing changed) | 2.18 s | **0.42 s** |
| One file changed | 2.12 s | 1.98 s |

The sessionStart budget is 3 s, so every case fits. The no-op path used to re-encode the whole
graph and parse cache through `json.dump`. Two changes fixed it: a fast path that leaves the
graph alone when the files, stamps and git state all match the last good build, and a cache
written with one `json.dumps` call (C encoder). `MAX_FILES` = 20,000 stops collection at that
size, and the builder warns when it does.

## Dashboard, 10,000 hook traces (50,000 events, 26 MB `events.jsonl`)

| Endpoint | Time |
|----------|------|
| First `all_traces` after server start (cold parse) | 1.52 s |
| `/api/requests` (50) | 0.02 s |
| `/api/conversations` (200, with savings) | 0.10 s |
| `/api/requests/<id>` (signals, impact, savings) | 0.04 s |
| `/api/skill-savings` | 0.21 s |
| `/api/index-health` | 0.03 s |
| `/api/risk` | 0.00 s |

Every page loads in under 1 s once the trace cache is warm. The cold parse happens once per
server start, and after that it reads only new bytes. Log retention (H-041) caps
`events.jsonl` at 5 MB of recent rows by default, which keeps even the cold parse well under 1 s.
